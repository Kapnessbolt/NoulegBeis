# Parts Radar - aggiornamento API test

## Riassunto

Lorenzo scrive a [[maurizio-fortuna]] (Head of Parts & SMR, Sales, di Solera | Kromeda, [[solera]]), in copia [[ignazio-romeo]] di [[assoricambi]], ADAC Bologna ([[adac-bologna]]), [[cristian-schifone]] e [[leonardo-pinsone]]. Kromeda si era detta disponibile ad aprire un servizio API di test a condizione di una proiezione di volumi oltre il singolo ricambista: Lorenzo risponde che Assoricambi, il consorzio dei ricambisti italiani, conosce e sostiene il progetto, e che un pilot riuscito porterebbe alla diffusione nella rete.

BlueAge chiede a Solera una proposta ufficiale su due fronti: il servizio API per la fase di validazione, con ADAC come ricambista che conduce i test sul campo, e il servizio a regime con modello di consumi e pricing.

Fortuna risponde che lo "stadio 2" del workflow tecnico di BlueAge (VIN → codice OE originale) tramite web service con VIN testuale è ancora in sviluppo: oggi la funzione esiste solo via Canvas grafico, la prima beta è prevista per fine settembre / ottobre e Solera ricontatterà BlueAge al rilascio.

## Decisioni e azioni

- [ ] Solera / Kromeda (M. Fortuna): ricontattare BlueAge al rilascio della beta del web service VIN testuale (previsione fine settembre / ottobre 2026)
- [ ] Solera / Kromeda: inviare la proposta ufficiale (API per la validazione con ADAC, servizio a regime con pricing)
